# دليل المساهمة في المشروع

## 1. بداية العمل

قبل البدء في أي مهمة:
1. اقرأ وثيقة المشروع الأساسية.
2. اقرأ المهام المخصصة لك.
3. تأكد من أن المطلوب واضح ومحدد.
4. تأكد من وجود Acceptance Criteria.

## 2. قواعد التنفيذ

- لا تبدأ في تطوير شيء غير موثق.
- لا تقم بتعديل جزء لا يخص المهمة الحالية.
- إذا كانت المهمة تحتاج تغيير في البنية، احصل على موافقة Tech Lead.
- إذا كنت ستغير قاعدة البيانات، أنشئ خطة migration واضحة.

## 3. قواعد الأمان

- لا تضع secrets أو keys في الـ repository.
- لا تنشر بيانات فعليه أو حساسة في الكود.
- استخدم التحقق من الصلاحيات في كل endpoint مهم.

## 4. قواعد Git

### إنشاء branch
- feature/...
- fix/...
- chore/...

### مثال
- feature/children-registration
- fix/tenant-subdomain-resolution

## 5. الكود

- اكتب اسماء واضحة.
- لا تكرّر المنطق.
- تابع نفس النمط الموجود في المشروع.
- لا تترك code comments غير واضحة أو مفرطة.

## 6. الاختبار

قبل إغلاق任务:
- تأكد أن الكود يعمل محليًا.
- أرسل أو أكتب test للـ feature.
- تحقق من حالات الخطأ.

## 7. مراجعة الطلب

عند فتح Pull Request:
- اكتب وصفًا واضحًا
- اذكر الملفات الأساسية المتأثرة
- اذكر كيف تم التحقق
- أرفق صورة أو حالات اختبار إن كانت مطلوبة

## 8. ما الذي يجب أن يقال عند التعثر

إذا واجهت مشكلة:
- لا تواصل تطوير غير مفهوم.
- اطلب المساعدة مبكرًا.
- اشرح المشكلة بشكل واضح.
- قدم ما تم اختباره وما هو المتوقع.

## 9. معيار القبول النهائي

المهمة لا تعتبر منتهية إلا إذا:
- تم تنفيذها
- تم اختبارها
- تم مراجعة الكود
- تم توثيقها إن احتاجت
- تم التزامها بأهداف المشروع
